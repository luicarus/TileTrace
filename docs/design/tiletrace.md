# Triton 张量变换可视化与 agent 接入设计

状态：第一版原型已实现并通过自动化验证和独立审查；agent 暂定 Codex，界面宿主为 VS Code。实时 IDE 布局、焦点与 Codex 对话仍需安装后验证。

## 目标

用户在编辑器或 agent 宿主中打开 Triton 脚本并选择表达式后，右侧面板展示该表达式的输入形状、输出形状、轴变化以及元素来源关系。第一版围绕张量变换开发，采用独立的数据结构、分析实现和交互设计。

输入条件不完整时显示符号形状和缺失参数，不编造具体结果。打开文件不执行脚本、导入用户模块或启动 kernel。

## 第一版范围

| 操作 | 展示内容 |
| --- | --- |
| `tl.arange` | 一维索引张量的形状与已知索引值 |
| `x[:, None]`、`x[None, :]`、`tl.expand_dims` | 新增轴的位置与元素对应关系 |
| 广播与简单逐元素运算 | 输入轴如何对齐；输出元素对应的输入位置 |
| `tl.reshape`、`x.reshape` | 元素数量约束、前后形状、可确定的逻辑元素映射 |
| `tl.trans`、`x.trans` | 轴置换与逻辑坐标映射 |
| `tl.sum`、`tl.max` | 被归约的轴、输出形状、每个输出位置的输入集合 |

`tl.program_id`、`tl.constexpr` 和简单标量算术用于构建分析上下文。输入张量或 `tl.load` 的结果可以作为形状来源，但第一版不建立独立的全局内存访问可视化模块。

首批例子：外积式广播、二维转置、向量 reshape 为二维张量、按行/按列归约、softmax 中归约结果再广播。

## 交互

1. 打开 Triton 文件，选择 kernel；宿主获得当前编辑缓冲区内容。
2. 分析可用的参数与形状关系，缺失参数由参数面板补充。
3. 选择代码表达式，显示“输入张量 → 当前操作 → 输出张量”。
4. 点击或悬停输出元素，高亮参与生成它的输入元素。
5. 修改参数或源码后重新分析，保留仍有效的选择；旧结果明确标记为过期。
6. 点击图中的操作定位对应源码。支持依赖路径上的前一步/后一步浏览，不将其表示为 GPU 执行时序。

张量维度默认命名为 axis 0、axis 1 等。只有取得明确语义时才标注 M、N、K 或行、列。高维张量通过固定其他轴查看二维切片，大张量通过视窗或采样查看，展示范围与完整逻辑形状分开。

## 架构

宿主适配层 → 静态分析核心 → 统一操作图 → 可视化面板。

- 宿主适配层：读取缓冲区、选择范围、参数输入、源码定位，以及文档版本管理。
- 静态分析核心：解析 Python AST；维护变量版本、符号表达式、形状和操作依赖；仅实现明确支持的 Triton 子集。
- 统一操作图：作为界面与 agent 的共同数据来源，避免为两端分别计算语义。
- 可视化面板：显示形状、轴和元素来源，支持代码联动。
- 可选 agent 工具接口：查询当前表达式、变换路径和诊断；agent 基于分析结果解释代码。工具接口本身不承担宿主面板创建。

核心分析器采用 Python；VS Code 扩展与面板采用 TypeScript。扩展通过本地分析进程传递 JSON 请求，MCP 服务复用相同的核心分析接口，供 Codex 或其他 MCP 客户端调用。

VS Code 扩展通过 Webview Panel 在编辑器右侧显示变换视图。它读取已保存文件当前未保存的编辑缓冲区和选择范围，提供源码定位；Codex 通过 MCP 获取同样的操作图与诊断。界面能力来自 VS Code 扩展，不依赖 agent 创建编辑器面板。第一版仅接入受信任工作区中的已保存 `.py` 文件。

分析与上下文发布分别使用独立进程，避免耗时分析阻塞过期状态同步。进程从可信 backend 目录使用隔离的 Python `-I -S` 启动，工作区代码不参与模块查找。每次重建进程分配新的会话 ID；浏览器坐标查询携带独立请求标识并验证返回的版本、节点和坐标。

## 数据契约

每次分析请求携带文档标识、源码内容、源码版本及用户参数。每个响应关联原始版本，宿主丢弃已过期的异步结果。

每个操作节点包含：

- 稳定操作标识、操作类型、输入与输出张量标识。
- 源码范围，包括起止行与列；明确分析器与宿主的字符编码约定并转换。
- 输入/输出 shape、dtype（已知时）、轴信息。
- 参数，例如 reshape 目标形状、转置排列、归约轴与 keep_dims。
- 可惰性查询的元素来源映射，不为大张量展开全部映射。
- 结果状态：已确定、符号推导、缺少输入或不支持。
- 诊断与假设，区分 Triton 合法性要求和可视化能力限制。

张量变换记录表示逻辑语义，不声称给出线程/warp 分布、GPU 寄存器布局、性能或实际访存轨迹。

## 分析边界

- 禁止通过执行用户表达式、导入用户脚本或运行 kernel 来补全静态分析结果。
- 对动态索引、复杂控制流、跨函数调用和未知操作返回明确诊断；第一版不承诺任意 Triton 脚本都能完整分析。
- `reshape` 元素数量无法验证时保留约束；允许元素重排的情形，只有能够证明映射时才显示精确连线。
- 不将逻辑 transpose/reshape 直接描述成全局内存搬运。
- 不根据名称 `BLOCK_M`、`BLOCK_N` 或 `rows` 推断语义；形状与依赖来自表达式。
- 不默认执行 autotune；用户选择具体配置或保留符号参数。
- 第一版可处理直线代码与编译期已知的分支；循环与运行时分支需要后续单独设计状态表示。

## Codex 接入方案

用户允许选择任意 agent，暂定 Codex。第一版以 VS Code 中的 Codex agent 为验证环境，独立 VS Code 扩展承载可视化界面，MCP 服务承载 agent 工具。无需依赖 Codex IDE 扩展的插件机制。

拟提供三个工具：

- `analyze_kernel`：接收源码、kernel 名、参数与源码版本，返回操作图、缺失输入与诊断。
- `inspect_transform`：接收操作标识和可选输出坐标，返回形状变化、轴信息与元素来源。
- `get_visualization_context`：读取指定界面会话的文档版本、所选操作和参数，供 agent 解释用户正在查看的内容。

已打开文件的上下文由 VS Code 扩展明确同步；MCP 不能自行获知用户当前打开的文件或选择范围。跨进程同步应使用明确的会话标识和版本，不用全局单一“当前文件”状态。界面直接读取对应会话的分析结果，避免依靠自然语言回复刷新图形。

Codex IDE 客户端支持外部 MCP 工具；官方文档当前说明 IDE 扩展不支持安装插件。这不影响另行开发普通 VS Code 扩展。官方 MCP Apps UI 快速入门把可选嵌入界面明确描述为 ChatGPT 的 iframe；不据此推断每种 Codex 客户端都支持相同面板能力。

后续可以为支持 MCP Apps 的宿主封装相同前端。ChatGPT Plugin Extensions 提供 conversation panels 和 file viewers，可作为额外适配目标；需要单独验证目标客户端及文件打开入口，不能把 MCP 工具可调用等同于文件打开时自动出现面板。

## 实现顺序与验收

1. 建立分析核心和数据契约，先验证 expand_dims、广播、transpose、reshape、归约的形状与来源规则。
2. 建立变换面板，通过固定示例展示前后形状和元素来源。
3. 完成 VS Code 扩展的缓冲区读取、选择联动、参数输入、源码反向定位和版本同步。
4. 接入 MCP 工具并通过 VS Code 中的 Codex agent 验证上下文读取与变换查询；打通真实 Triton 子集脚本，补充不支持语法的可理解诊断。

验收用例：

- `[2] → [2,1]` 与 `[3] → [1,3]` 广播成 `[2,3]`，每个输出位置正确映射到两个输入。
- `[2,3]` 转置成 `[3,2]`，点击输出 `(j,i)` 高亮输入 `(i,j)`。
- `[8]` reshape 为 `[2,4]`，默认语义下保持正确的逻辑元素对应。
- `[2,4]` 沿 axis 1 归约得到 `[2]`，开启 keep_dims 时得到 `[2,1]`。
- 输出归约结果再次广播时，依赖路径完整，输出元素高亮正确的来源集合。
- 参数不足、形状不匹配和不支持操作都有明确诊断。
- 快速编辑与切换文件不会显示其他文档或旧版本的分析结果。

其中 `[2,3]` 用于独立的形状规则验证；端到端 Triton 示例采用目标版本实际允许的张量形状与操作。
